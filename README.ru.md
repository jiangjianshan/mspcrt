## Обзор проекта

Хотя существуют превосходные проекты с открытым исходным кодом, такие как [gnulib](https://www.gnu.org/software/gnulib/), [mingw-w64](https://www.mingw-w64.org/) и [glibc](https://www.gnu.org/software/libc/), которые частично или полностью реализуют POSIX-стандартные заголовочные файлы и функции, мы все же создали `mspcrt` (MSVC Posix C Runtime), в основном по следующим причинам:

- **gnulib** требует встраивания в проект исходного кода на основе Autotools, что не подходит для проектов, не использующих Autotools для сборки.
- **MinGW-w64** в первую очередь ориентирован на компилятор MinGW, тогда как `mspcrt` специально разработан для компиляторов MSVC или подобных MSVC.
- **glibc** построена вокруг GCC. Хотя существует старый проект [GnuWin](https://gnuwin32.sourceforge.net/), который портировал glibc на платформу Win32, более новые порты отсутствуют, и имеются конфликты совместимости с MSVC.
- Библиотека [UCRT](https://learn.microsoft.com/en-us/cpp/porting/upgrade-your-code-to-the-universal-crt?view=msvc-170) в Windows SDK реализует только подмножество POSIX-стандартных функций, многие отсутствуют, что вызывает трудности при компиляции многих проектов с открытым исходным кодом с помощью MSVC.

`mspcrt` можно рассматривать как дополняющий проект для библиотеки UCRT. Изначально он был подготовлен для облегчения компиляции библиотек с открытым исходным кодом, которые зависят от POSIX-стандартных заголовков, в рамках проекта [msforge](https://github.com/jiangjianshan/msforge). Он направлен на решение проблем компиляции MSVC, вызванных отсутствием POSIX-стандартных заголовочных файлов или функций в UCRT.

Учитывая фундаментальные различия между Linux и Windows на уровне базовых механизмов, полная реализация всех POSIX-стандартных функций была бы огромной работой. Поэтому `mspcrt` не будет заново реализовывать существующие excellentные проекты с открытым исходным кодом, такие как:
- [getopt-2022-09-25](https://www.codeproject.com/articles/Full-getopt-Port-for-Unicode-and-Multibyte-Microso) (ссылка, похоже, неактивна)
- [dirent](https://github.com/tronkko/dirent)
- [dlfcn-win32](https://github.com/dlfcn-win32/dlfcn-win32)
- [winpthreads](https://github.com/mingw-w64/mingw-w64/tree/master/mingw-w64-libraries/winpthreads)

Среди них `getopt` был напрямую интегрирован в `mspcrt` в качестве сторонней библиотеки; другие компоненты приоритетно компилируются как зависимости `mspcrt` в рамках [msforge](https://github.com/jiangjianshan/msforge).

## Быстрый старт
```bash
git clone https://github.com/jiangjianshan/mspcrt
cd mspcrt
cmake -B build .
```

Более рекомендуемый подход — использовать `msforge` для управления зависимостями и средой сборки:

```bash
git clone https://github.com/jiangjianshan/msforge
cd msforge
# Скомпилировать библиотеки зависимостей mspcrt (dirent, dlfcn-win32, winpthreads), затем скомпилировать mspcrt
mpt mspcrt
```

## Стратегия реализации

`mspcrt` применяет стратегию инкрементальной реализации. Добавление и реализация каждого POSIX-заголовка требуют тщательной оценки, потому что неполные реализации или несоответствия между определениями макросов и функциями могут привести к ошибкам компиляции в библиотеках с открытым исходным кодом. Более того, некоторые библиотеки с открытым исходным кодом предоставляют свои собственные кроссплатформенные реализации, что может вызвать конфликты.

Поэтому первоначальная версия `mspcrt` реализует только POSIX-заголовки и функции, отсутствующие в UCRT, и прошла тесты компиляции с почти 355+ библиотеками с открытым исходным кодом в [msforge](https://github.com/jiangjianshan/msforge). По мере увеличения количества библиотек с открытым исходным кодом, поддерживаемых `msforge`, `mspcrt` будет постепенно дополнять недостающие POSIX-компоненты.

Наша цель — не реализовать весь стандарт POSIX, а сосредоточиться на помощи `msforge` и другим проектам в успешной компиляции большего количества проектов с открытым исходным кодом, соответствующих стандарту POSIX, на платформе Windows с использованием компиляторов MSVC или подобных MSVC.

## Статус проекта и План развития

### Текущий прогресс
- ✅ Пройдены тесты компиляции с 355+ библиотеками с открытым исходным кодом
- ✅ Бесшовная интеграция с такими проектами, как dirent, dlfcn-win32, winpthreads
- 🔄 Постоянное расширение охвата POSIX-функций

### Краткосрочные цели
- Добавить реализации для Windows для большего количества POSIX-системных вызовов
- Улучшить совместимость с функциями, специфичными для Linux
- Оптимизировать производительность и использование памяти

### Долгосрочное видение
- Стать полным слоем совместимости POSIX, дополняющим библиотеку UCRT в Windows SDK (Если бы UCRT в будущем полностью поддерживал стандарт POSIX, как glibc, `mspcrt` потенциально мог бы быть упразднен.)
- Поддерживать компиляцию большего количества проектов с открытым исходным кодом в Windows без изменений
- Построить активное сообщество разработчиков

1. **Сделайте форк этого репозитория** и клонируйте его локально.
